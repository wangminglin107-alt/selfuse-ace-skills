# Zotero—Obsidian 真实同步审计

日期：2026-08-26

## 验证结果

- Zotero 10.0.1 中存在且只存在一个 `Pilot｜GSMA情绪与互动` 文件夹。
- 文件夹包含 3 条预期记录，条目键与本地映射状态一致。
- Obsidian 同步库生成 3 篇来源笔记和 1 篇项目总览。
- 第二次原样运行全部为 `skip`；3 篇来源笔记的字节哈希与修改时间均未变化。
- 桥接只提供创建、复用和加入文件夹能力，没有删除操作。

## 已发现问题

- [已修复] Zotero 人工授权原来只有 10 秒等待时间，容易在用户点击前超时；默认等待已增加到 60 秒并加入回归测试。
- [已修复] 授权拒绝或协议异常原来可能直接显示技术回溯；现在返回明确的阻止状态且不落盘半成品映射。
- [后续] 来源 Markdown 自带 YAML 属性区时，会在 Obsidian 自动生成区内再次显示一份属性区。内容可用，但阅读界面略显重复。
- [后续] 已有笔记刷新时只替换自动区，笔记顶部的 `title/year/source_sha256` 属性尚未同步更新；这不影响本轮新增笔记，但应在元数据更正场景补齐。
- [后续] 当前桥接只写文献元数据与研究笔记，不自动附加 PDF。这样更安全、更轻量，但需要附件工作流时应新增独立 capability，不能塞进基础同步器。

## 改进计划

1. 在下一版为 Obsidian writer 增加“剥离来源属性区 + 更新受管属性”的测试和迁移逻辑，同时继续保护 `我的想法` 等人工区域。
2. 增加可选的 `attachment-ingest` capability：只对许可证、来源和文件哈希均明确的 PDF 建立 Zotero 附件，不改变基础桥接的默认行为。
3. 增加项目级索引的自动刷新，但保留本轮采用的人工可编辑总览，避免每次文献同步消耗模型 token。

## 结论

最小方案可用，并且符合节省 token 的目标：确定性同步器只比较元数据和 SHA-256；只有新增或内容变化的来源才进入阅读与笔记刷新流程。
